# linkcare-sample

位置情報・端末情報の共有アプリ「LinkCare」（個人開発中）の簡易サンプルです。

実物のソースコードは開発中のため、実績紹介用に、基本設計の核となる「アカウント連携 → 共有許可 → 位置情報の共有 → 連携解除」の流れだけを小さく再現したAPIサンプルを公開しています。

## 実物（LinkCare）について

- 位置情報・移動履歴、バッテリーや端末状態、セキュリティ情報を、アカウント同士で共有できるアプリ（iPhone / Android）
- 構成：FastAPI + PostgreSQL / PostGIS + Redis（バックエンド）、Flutter（アプリ）、React（管理画面）
- 共有は項目ごとに細かく許可でき、連携を解除すると即座に共有が止まる設計
- カメラ共有は端末間 WebRTC の直接通信（サーバーはシグナリングのみ）

## このサンプルの内容

FastAPI + SQLite で、以下の一連の流れを実装しています。

| 操作 | エンドポイント |
|---|---|
| ヘルスチェック | `GET /api/v1/health` |
| ユーザー登録（トークン発行） | `POST /api/v1/users` |
| 端末登録 | `POST /api/v1/devices` |
| 位置情報の投稿 | `POST /api/v1/locations` |
| 連携の一覧（送った・届いた・承認済み） | `GET /api/v1/links` |
| 連携リクエスト | `POST /api/v1/links` |
| 連携の承認 | `POST /api/v1/links/{id}/approve` |
| 連携の解除・リクエストの取り消し／拒否 | `DELETE /api/v1/links/{id}` |
| 共有許可の設定 | `PUT /api/v1/permissions` |
| 共有された最新位置の取得 | `GET /api/v1/locations/shared` |

### 設計上のポイント

- **共有は片方向・本人の許可制**：連携が承認されても、相手が許可をオンにするまで位置は見えない。許可は自分→相手の向きごとに設定する
- **解除で即停止**：連携を解除すると、その時点で共有が止まる。共有許可も双方向で削除されるため、再連携しても許可は自動で復活しない
- **不正な操作を弾く**：自分自身・存在しない相手・重複した連携リクエスト、未連携の相手への許可設定、範囲外の緯度経度、他人の端末への位置投稿はエラーになる
- **トークンの扱い**：トークンはDBにハッシュ（SHA-256）だけを保存し、平文を返すのは発行時の1回のみ。有効期限は30日

認証は簡易化のため `X-Token` ヘッダー方式にしています（実物では JWT + リフレッシュトークン）。共有の項目もサンプルでは位置情報（`location`）のみです。

## 実行方法

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

起動後、http://127.0.0.1:8000/docs でAPIドキュメント（Swagger UI）が確認できます。データは `sample.db` に保存されます（環境変数 `LINKCARE_DB` で保存先を変更可能）。

## テスト

```bash
pytest -q
```

連携→承認→許可→共有、解除による即時停止、再連携時に許可が復活しないこと、第三者からは見えないこと、各種入力チェック、トークンの有効期限などを確認する29本のテストがあります。テストは一時DBを使うため、`sample.db` は作られません。

## 備考

- サンプル内のデータはすべて架空のものです。
